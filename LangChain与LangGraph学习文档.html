01 · Ecosystem

四个产品，一个分层矩阵 / 生态全景

LangChain 不是单一框架，而是覆盖 AI Agent 全生命周期的产品矩阵。LangGraph 在底层做编排运行时，LangChain（create_agent）在中间提供最小 Agent 循环，Deep Agents 在顶层提供开箱即用的外壳，LangSmith 横跨所有层做可观测、评估与部署。

四产品职责一览
产品定位关键作用
LangChainAgent 框架模型、工具、Agent 循环的抽象与集成
LangGraph编排运行时持久执行、流式、人机交互、持久化
Deep AgentsAgent 外壳内置规划、子 Agent、文件系统、上下文管理
LangSmith平台追踪、评估、提示词、部署

Deep Agents适合「开箱即用」跑生产级 Agent；LangChain适合快速交付 + 中间件定制；LangGraph适合确定性工作流与 Agent 工作流混合；LangSmith可追踪任意框架。

02 · Quickstart

create_agent 是极简 Agent 外壳 / LangChain 入门

LangChain 用模型、工具、提示词和中间件组合出恰好符合用例的 Agent，支持 OpenAI、Anthropic、Google 等多家提供商。

安装

bash
pip install -U langchain            # 核心（Python 3.10+）
pip install -U langchain-openai     # OpenAI 集成
pip install -U langchain-anthropic  # Anthropic 集成

第一个 Agent

python
from langchain.agents import create_agent

def get_weather(city: str) -> str:
    """Get weather for a given city."""
    return f"It's always sunny in {city}!"

agent = create_agent(
    model="openai:gpt-6.1-sol",
    tools=[get_weather],
    system_prompt="You are a helpful assistant",
)
result = agent.invoke(
    {"messages": [{"role": "user", "content": "What's the weather in San Francisco?"}]}
)
print(result["messages"][-1].content_blocks)

配置 API key（.env 可用 python-dotenv 的 load_dotenv()）：

bash
export OPENAI_API_KEY="your-api-key"
export ANTHROPIC_API_KEY="your-api-key"
export GOOGLE_API_KEY="your-api-key"

LangChain vs Deep AgentDeep Agent 内置规划（write_todos）、虚拟文件系统（grep/read_file）、子 Agent 派生，能真正回答「文件里有多少行包含 Gatsby」这类需执行代码的问题；普通 LangChain Agent 缺少这些工具时只能返回估算值或 null。

03 · Concepts

Agent 是模型加外壳 / 核心概念

  • Agent：模型在循环中调用工具直到任务完成。
  • Harness：循环之外的一切——提示词、工具、中间件。职责是「在正确的时间把正确的上下文给模型」。

模型与工具

python
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain.tools import tool

model = init_chat_model("openai:gpt-6.1-sol", temperature=0.5, timeout=300)

@tool
def search(query: str) -> str:
    """Search for information."""
    return f"Results for: {query}"

agent = create_agent(model=model, tools=[search])

工具的 name、description、参数名会成为模型 prompt 的一部分，所以要写清楚。

结构化输出与状态

python
from pydantic import BaseModel
from langchain.agents import AgentState, create_agent

class Answer(BaseModel):
    summary: str
    confidence: float

class MyState(AgentState):
    user_id: str
    call_count: int

agent = create_agent(model="openai:gpt-6.1-sol", tools=[], response_format=Answer, state_schema=MyState)

用 thread_id 持久化对话

python
from langchain_core.utils.uuid import uuid7
from langgraph.checkpoint.memory import InMemorySaver

agent = create_agent(model="openai:gpt-6.1-sol", tools=[], checkpointer=InMemorySaver())
config = {"configurable": {"thread_id": str(uuid7())}}

agent.invoke({"messages": [{"role": "user", "content": "weather?"}]}, config=config)
# 复用同一 thread_id 以保留历史
agent.invoke({"messages": [{"role": "user", "content": "tomorrow?"}]}, config=config)

核心优势：标准模型接口（一行换模型）、高度可配置 harness、构建于 LangGraph 之上、用 LangSmith 调试。

04 · Quickstart

工作流 = 状态 + 节点 + 边 / LangGraph 入门

LangGraph 是面向长时间运行、有状态 Agent 的低级编排框架，把工作流定义为共享状态、节点、边组成的图，可混合确定性步骤与 LLM 驱动步骤。

安装与最小图

bash
pip install -U langgraph
python
from langgraph.graph import StateGraph, MessagesState, START, END

def mock_llm(state: MessagesState):
    return {"messages": [{"role": "ai", "content": "hello world"}]}

graph = StateGraph(MessagesState)
graph.add_node(mock_llm)
graph.add_edge(START, "mock_llm")
graph.add_edge("mock_llm", END)
graph = graph.compile()
graph.invoke({"messages": [{"role": "user", "content": "hi!"}]})

完整计算器 Agent（8 步）

python
from langchain.tools import tool
from langchain.chat_models import init_chat_model

model = init_chat_model("claude-sonnet-4-6", temperature=0)

@tool
def multiply(a: int, b: int) -> int:
    """Multiply `a` and `b`."""; return a * b

@tool
def add(a: int, b: int) -> int:
    """Adds `a` and `b`."""; return a + b

@tool
def divide(a: int, b: int) -> float:
    """Divide `a` and `b`."""; return a / b

tools = [add, multiply, divide]
tools_by_name = {t.name: t for t in tools}
model_with_tools = model.bind_tools(tools)

# 状态：operator.add 追加消息而非替换
from langchain.messages import AnyMessage
from typing_extensions import TypedDict, Annotated
import operator

class MessagesState(TypedDict):
    messages: Annotated[list[AnyMessage], operator.add]
    llm_calls: int

from langchain.messages import SystemMessage, ToolMessage

def llm_call(state: dict):
    return {
        "messages": [model_with_tools.invoke(
            [SystemMessage(content="You are a helpful assistant tasked with performing arithmetic on a set of inputs.")]
            + state["messages"]
        )],
        "llm_calls": state.get('llm_calls', 0) + 1
    }

def tool_node(state: dict):
    result = []
    for tc in state["messages"][-1].tool_calls:
        obs = tools_by_name[tc["name"]].invoke(tc["args"])
        result.append(ToolMessage(content=obs, tool_call_id=tc["id"]))
    return {"messages": result}

from typing import Literal
from langgraph.graph import StateGraph, START, END

def should_continue(state: MessagesState) -> Literal["tool_node", END]:
    return "tool_node" if state["messages"][-1].tool_calls else END

b = StateGraph(MessagesState)
b.add_node("llm_call", llm_call)
b.add_node("tool_node", tool_node)
b.add_edge(START, "llm_call")
b.add_conditional_edges("llm_call", should_continue, ["tool_node", END])
b.add_edge("tool_node", "llm_call")
agent = b.compile()

from langchain.messages import HumanMessage
messages = agent.invoke({"messages": [HumanMessage(content="Add 3 and 4.")]})
for m in messages["messages"]:
    m.pretty_print()

05 · Graph API

节点做工作，边决定下一步 / 图的核心概念

State 是共享快照，Nodes 是读取状态并返回更新的函数，Edges 是决定下一个节点的转换。Send 做 fan-out，Command 在更新状态的同时路由。

状态与 Reducer

状态存于 channels。大多数 channel 用 last-write-wins，带 reducer 的用组合方式合并。

python
import operator
from typing import Annotated
from typing_extensions import TypedDict

class State(TypedDict):
    foo: int                                # 覆盖
    bar: Annotated[list[str], operator.add] # 追加合并

# 消息状态：用 add_messages 而非 operator.add
from langchain.messages import AnyMessage
from langgraph.graph.message import add_messages

class GraphState(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]

add_messages能在人机交互编辑时按 ID 就地更新已有消息，operator.add 只能追加。

节点与边

python
def node_a(state: State):
    return {"text": state["text"] + "a"}

graph = (
    StateGraph(State)
    .add_node("node_a", node_a)
    .add_edge(START, "node_a")
    .add_edge("node_a", END)
    .compile()
)
graph.invoke({"text": ""})  # {'text': 'a'}

边分普通边与条件边；入口用 START 连接。每个节点要么用静态边，要么用动态路由（条件边/Command），不要混用。

Send（扇出）与 Command（状态+路由）

python
from langgraph.types import Send, Command
from typing import Literal

# 每个 item 运行一次同一节点，item 数量运行时才知道
def fan_out(state):
    return [Send("generate_joke", {"subject": s}) for s in state["subjects"]]

def my_node(state) -> Command[Literal["next_node"]]:
    return Command(update={"foo": "bar"}, goto="next_node")

重执行与幂等checkpointer 在 super-step 边界存 checkpoint，节点内部不存。中断或重试后节点从头重跑，要用幂等键、upsert、先读后写检查。

06 · Capabilities

持久化、中断、流式是核心能力 / 关键能力

持久化（短期 + 长期记忆）

python
from langgraph.checkpoint.memory import InMemorySaver

graph = builder.compile(checkpointer=InMemorySaver())
config = {"configurable": {"thread_id": "thread-1"}}
graph.invoke({"messages": [...]}, config=config)

checkpointers（PostgresSaver / SqliteSaver / MemorySaver）做短期线程作用域记忆；stores 做跨线程长期记忆。

中断（Human-in-the-loop）

python
from langgraph.types import interrupt, Command

def approval_node(state):
    approved = interrupt("Do you approve this action?")
    return {"approved": approved}

# 中断后恢复
graph.stream_events(Command(resume=True), config=config, version="v3")

中断规则① 不要用 try/except 包裹 interrupt；② 不要重排节点内 interrupt 顺序；③ 不要返回复杂值；④ 中断前副作用必须幂等。

流式（Streaming）

python
for chunk in graph.stream({"topic": "ice cream"}, stream_mode=["updates", "custom"], version="v2"):
    if chunk["type"] == "updates":
        for node_name, state in chunk["data"].items():
            print(f"Node {node_name} updated: {state}")

Stream modes：updates、values、messages、custom、checkpoints、tasks、debug；新应用推荐 event streaming（stream_events(version="v3")）。

08 · Selection

按任务复杂度选框架 / 对比与选型

三者定位差异
产品层级最佳场景
LangGraph运行时需精细控制、持久化、人机交互的生产系统
LangChain框架从零构建 prompt/tools；快速交付 + 中间件定制
Deep Agents外壳长期自主 Agent，内置规划、文件系统、子 Agent

快速原型/换模型 → LangChain；精确控制状态流程 → LangGraph；长期复杂任务 → Deep Agents；可观测/评估/部署 → 配套 LangSmith（框架无关）。

09 · Timeline

从 Chains 到 Agent 抽象 / 演进时间线

2022-10-24
LangChain 作为 Python 包发布（早于 ChatGPT 一个月），含 LLM 抽象 + Chains。
2023-02
LangChain Inc. 成立；目标「让智能 Agent 无处不在」。
2023-03
OpenAI 发布 function calling，LangChain 改用此方式做工具调用。
2023-06
LangSmith 发布（闭源平台，可观测 + 评估）。
2024-01
LangChain 发布 0.1.0（首个非 0.0.x 版本，聚焦稳定性）。
2024-02
LangGraph 作为开源库发布，补齐低级编排层。
2024-06
集成超 700 个，拆分为独立 provider 包或 langchain-community。
2025-04
更新 message 格式以支持多模态输入。
2025-10-20
LangChain 发布 1.0，chains/agents 重构为单一 Agent 抽象（基于 LangGraph）。
2026-03-15
Deep Agents 作为开源 Agent 外壳发布（v0.5.3）。
